# Script Quality Checklist

Run this checklist before presenting any draft or revision.

---

## Structure

- [ ] Intro follows: Context > Common Belief > Contrarian > Proof > Plan
- [ ] Intro under 60 seconds
- [ ] Body points follow ascending value (each better than the last)
- [ ] Re-hooks every 60-90 seconds
- [ ] Each point has What > Why > How (Value Loop)
- [ ] ONE ending, not multiple
- [ ] Matches a proven outlier pattern from research

---

## Content & Value

- [ ] All examples use specific numbers ($47K, 3 entities, Section 199A)
- [ ] Client stories are anonymized but specific (income level, entity count, property count)
- [ ] At least 2 IRC sections, rulings, or specific tax code references cited
- [ ] Passes the "Could any CPA have written this?" test. If yes, add specificity or a lived experience.
- [ ] Beyond basic. Not something they'd find in a 2-minute Google search.
- [ ] Actionable. Viewer can do something specific after watching.
- [ ] Each legal point is translated to plain English immediately after citing

---

## Persona Fit

- [ ] Examples use $250K-$3M+ income levels
- [ ] Addresses multi-entity or multi-asset situations
- [ ] Positions proactive planning as the answer (not reactive compliance)
- [ ] Makes Anthony the CPA who "gets it"
- [ ] Speaks as a peer to high-net-worth clients, not talking down

---

## Voice

- [ ] Zero script killers present (see [[wiki/youtube-scripts/script-killers.md]])
- [ ] Contains Anthony's signature phrases ("Here's what I see all the time," "That's not a strategy. That's compliance.")
- [ ] Uses Anthony's transition patterns (not generic "moving on" or "next up")
- [ ] No em dashes anywhere in the script
- [ ] Reads like speaking, not writing (read aloud test)
- [ ] Specific numbers throughout, never vague claims

---

## Tax Authority

- [ ] Legal basis cited for every major claim (IRC sections, regulations, or rulings)
- [ ] When a multi-part test applies, each element is walked through
- [ ] Evidence is stacked (2-3 references per major point, not just one)
- [ ] Every legal citation is followed by a plain English translation
- [ ] Implementation steps included, not just theory ("here's how you actually do this")
- [ ] Disclaimers handled naturally, not dumped in a block

---

## Client Story Integration

- [ ] At least one detailed client story per major section
- [ ] Each story follows: Setup > Problem > Fix > Result
- [ ] Results include specific dollar amounts and timeframes
- [ ] Stories are anonymized but feel real (income, entity type, property count)
- [ ] At least one story highlights "what your CPA missed"

---

## Production Readiness

- [ ] `**[B-ROLL]**` callouts placed where visuals should change
- [ ] `**[ON-SCREEN TEXT]**` where numbers or key phrases should appear
- [ ] `**[GRAPHIC]**` where diagrams or comparisons should display
- [ ] Tax code citations marked for on-screen display
- [ ] Timing estimates are realistic for spoken delivery

---

## Learnings Applied (Proactive)

- [ ] Tightened everything (first drafts are always too long)
- [ ] Gets to value fast (no over-explaining setup)
- [ ] Combined related points (grouped where possible)
- [ ] Uses real client scenarios, not theoretical
- [ ] Cut filler phrases
- [ ] One deep example over multiple shallow ones

---

## Final Read-Through

- [ ] Read aloud. Does it sound like Anthony?
- [ ] Compare energy to example scripts in best-work
- [ ] Verify timing estimates are realistic
- [ ] Confirm ascending value throughout the body
- [ ] Check that the close has ONE action item, not three
